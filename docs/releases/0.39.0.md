# v0.39.0 — Income correction & money-flow integrity

This release closes the remaining correction gap at the start of Poolamkoo's money flow. An incoming-money row can still be corrected in place, but the correction may no longer rewrite history that has already been executed.

## What changed

- Added `lib/income-correction.ts` as the pure correction boundary for incoming-money edits.
- A corrected amount can never be lower than money already executed from that income.
- When the amount changes, only the still-unexecuted portion of plan cards is rescaled; executed amounts remain hard floors.
- Fully executed plan cards stay fixed when an income is increased, leaving the new difference intentionally unplanned instead of inventing a new execution target.
- Allocation rows are synchronized to the corrected plan totals with exact integer-Toman distribution.
- Linked investment buys are checked as an additional execution floor, protecting against stale plan-progress metadata.
- Once execution has started, the income date is locked. This prevents the source money from being moved after already-recorded fund/investment execution dates.
- New and edited income dates cannot be in the future.
- Every valid income correction creates a local Recovery Snapshot before the write.
- The final write re-reads and re-validates the current income, plan, allocation and linked-transaction state inside one Dexie transaction before mutating anything.

## Compatibility

- IndexedDB stays on schema 8.
- No backup, Recovery Snapshot or Device Transfer format changes.
- No market-provider changes.
- No new environment variables or hosted financial storage.
- Background Push remains paused by default.

## Release QA

The pure correction suite covers reductions below executed money, proportional rescaling of only remaining plan money, fully executed plans, date locking, stale investment-plan progress and exact allocation rounding. Existing release gates continue to cover schema 6→8 migration, local data safety, production build, navigation, Reports and PWA boundaries.
