# Poolamkoo 0.36.0 — Investment transaction correction & ledger integrity

v0.36 moves from market/migration hardening back to a direct portfolio workflow gap: users can now correct an investment transaction without deleting and recreating it, while Poolamkoo protects the historical quantity ledger from impossible states.

> Release hotfixes: the Income Plan purchase dialog now passes the full transaction ledger required by the new chronological validator, and ledger validation feedback is stored in React Hook Form root errors instead of synchronously calling local `setState` from the dialog reset effect. These fix the pre-release strict TypeScript and React 19 lint gates without changing runtime data contracts.

## What changed

- Investment transaction rows now expose Edit on desktop and mobile.
- The edit dialog restores type, amount, unit price, date and optional note while keeping the original asset and plan/income links stable.
- A pure chronological ledger validator checks every add/edit against the full recorded history for that asset.
- A backdated sell is rejected if those units did not exist on that date, even when today's final quantity would be sufficient.
- Reducing or moving an older buy is rejected when a later recorded sell depends on those units.
- Deleting an investment transaction is also rejected when the remaining ledger would make a later sell impossible.
- Same-day buys are treated as available before same-day sells because Poolamkoo stores only a transaction date, not an intraday execution time.
- A Recovery Snapshot is created before every in-place transaction edit, and linked investment plan execution is recalculated after edit/delete.
- Transaction notes can now be added or corrected from the same dialog.

## Safety boundaries

- Editing a historical transaction never updates `manualPriceToman`; a current manual fallback price remains an explicit user value rather than a side effect of correcting history.
- New transactions for manual-price assets keep the existing behavior of optionally seeding the manual price from the newly entered trade.
- The validator never invents holdings or prices; it only checks recorded quantities and dates.
- Asset identity is not changed by the edit flow. If a trade was recorded against the wrong asset, delete/recreate remains the explicit correction path.
- No new backend, account, telemetry or hosted financial storage is introduced.

## Compatibility

- App version: `0.36.0`
- IndexedDB schema: `7` (unchanged)
- Backup/Recovery/Device Transfer formats: unchanged
- Service Worker cache: `poolamkoo-v60`
- Market provider priority and Background Push policy: unchanged
