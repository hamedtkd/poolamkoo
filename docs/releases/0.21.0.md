# v0.21.0 — Verified backups and restore safety

This release hardens the most important local-first escape hatch: getting financial data safely out of the browser and restoring it without guessing about compatibility.

## Verified backup files

- New exported backups use Envelope version 2.
- v2 stores the application version and local database schema version alongside the exported timestamp.
- A SHA-256 digest detects accidental corruption/truncation before restore starts.
- Encrypted files continue to use PBKDF2-SHA256 + AES-GCM; AES-GCM remains the authenticated encryption layer.
- Existing v1 backup files remain readable.

## Restore preview and compatibility gate

- Restore is now a two-step flow: inspect first, replace second.
- The app decrypts when needed, validates the envelope, validates required local-first tables/settings, and shows record counts before replacement.
- Backups created by a newer local schema are rejected before a recovery snapshot or destructive import begins.
- A fresh Recovery Snapshot is still created immediately before the confirmed restore.

## Recovery and device transfer

- New Recovery Snapshots carry `schemaVersion` and `appVersion` metadata.
- Legacy snapshots without metadata remain readable after structural validation.
- Direct WebRTC transfer now advertises the sender schema version and rejects future-schema data before import.
- The direct-transfer encrypted envelope intentionally remains v1 for backward friendliness; WebRTC transfer integrity continues to use an outer SHA-256 digest plus AES-GCM.

## PWA/release alignment

- Service Worker cache moves to `poolamkoo-v37` so the new restore UI and portability logic activate as one release.
- Background Push remains paused; no server database, account system, scheduler, Redis or new paid infrastructure is introduced.

## QA focus

Release verification should cover a v2 encrypted backup round-trip, a legacy v1 restore, a deliberately corrupted v2 file, a future-schema rejection, and the normal `npm run check` / `npm run build` gates.
