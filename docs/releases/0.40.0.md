# v0.40.0 — Local data health & consistency audit

## Why

Poolamkoo now has several intentional sources of truth: incoming-money plans, investment transactions, the fund movement ledger, archived asset lifecycle and provider-scoped market identity. Those boundaries prevent many new inconsistencies, but older/restored data or interrupted historical versions can still contain cross-table drift that a single feature screen cannot explain.

## What changed

- Settings gains **Local data health**, an on-device audit that reads IndexedDB only after the app has already bootstrapped.
- The pure audit detects missing/orphan references between Income, Allocation, Plan, Transaction, Fund and Asset rows.
- Fund history is replayed chronologically; negative history, invalid movements and a positive balance without any ledger are treated as manual-review errors.
- `fund.currentToman` drift is treated differently: when the movement ledger itself is valid, the displayed balance is deterministic and can be rebuilt safely.
- Investment history reuses the chronological quantity validator so historical oversells are surfaced.
- Asset-target Plan execution is compared with linked buy transactions. Stale `executedToman` is repairable only when linked buys exist; a historical execution with no linked buy is reported but left untouched because its origin is ambiguous. Execution overrun or a missing target also remains a manual-review issue.
- Archived assets with open holdings are reported as a warning and remain user-controlled through the existing restore flow.
- Duplicate provider-scoped Watchlist identity, invalid alerts and exact duplicate alert conditions are reported locally.
- Safe repair creates a Recovery Snapshot first, then re-reads the authoritative Fund/Movement/Plan/Transaction tables in one Dexie transaction before writing.
- Repair never deletes orphan rows, invents missing transactions, changes a plan target, repairs a negative ledger, or guesses at ambiguous history.

## Privacy and storage boundary

The audit and repair are entirely local. No financial value, entity name, issue list or health result is uploaded or added to analytics. IndexedDB remains **schema 8**; backup envelopes, Recovery payload format and Device Transfer protocol are unchanged.

## Release checks

- Pure tests cover healthy state, repairable Fund drift, missing/negative Fund history, historical investment oversell, orphan links, archived open holdings, Plan execution drift/overrun, duplicate market identity and money-rule state.
- Static regression gates require the Settings card, Recovery-Snapshot-backed repair boundary and unchanged schema 8.
- No extra browser release scenario is added because the new invariants are deterministic pure/store logic and the existing production-browser gate already covers Settings route continuity.
