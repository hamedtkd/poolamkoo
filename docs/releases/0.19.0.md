# v0.19.0 — Landing page and production hardening

This release separates the public product website from the local-first application and hardens failure/offline behavior before adding more financial features.

## Public landing page

- `/` is now a public Persian landing page that explains the incoming-money workflow, Local-first ownership, encrypted backup, device transfer, market integration, open-source status, and analytics boundaries.
- The financial application now starts at `/dashboard`.
- The PWA `start_url`, desktop sidebar, mobile navigation, support prompt, and public CTA all point to `/dashboard`.
- Moving from `/` to `/dashboard` does **not** migrate or recreate IndexedDB. Browser storage is scoped to the origin, so existing local data on the same deployed hostname remains available.

## Search and metadata boundaries

- Public informational pages are included in `sitemap.xml`.
- `robots.txt` disallows application routes and API routes.
- The `(workspace)` route group exports `noindex` metadata, keeping financial UI out of search results even if a crawler ignores the sitemap.
- The root metadata now has a stable metadata base and optional `NEXT_PUBLIC_SITE_URL` override for future custom domains.

## Local data boot hardening

- Public pages no longer create or seed the financial IndexedDB merely by being opened.
- The app bootstrap explicitly tracks IndexedDB readiness and surfaces a safe recovery screen after an error or a 12-second blocked-storage timeout.
- The recovery screen warns users not to clear Site Data as a first troubleshooting step.
- Existing repair behavior remains available through the route error boundary without adding a destructive reset action.

## Offline and error UX

- The app shell shows a small offline status banner while keeping local data usable.
- The offline fallback explains which features remain local and which market features require connectivity.
- Added a global error screen and a dedicated 404 page.
- App error handling now reports failed repair attempts instead of silently returning to the same state.
- Keyboard users get skip links on both public and application shells.

## Deployment hardening

- Added `X-Frame-Options: DENY` and disabled DNS prefetching in the common response headers.
- Service worker cache bumped to `poolamkoo-v33` and the landing/app entry pages are included in the precache list.
- Background Push remains disabled and no paid infrastructure is introduced.

## QA focus

Release checks cover:

- landing page / app route separation;
- private financial route indexing boundaries;
- IndexedDB bootstrap failure handling;
- offline communication;
- PWA start URL and navigation consistency;
- existing privacy-first analytics and Local-first regression gates.
