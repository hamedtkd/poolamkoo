# v0.41.0 — Unified financial activity history

## What changed

Poolamkoo now exposes one read-only **Activity** timeline for the financial events that are already stored locally. It combines incoming-money records, Fund Movement ledger rows, and investment buy/sell transactions without introducing an expense ledger or a synthetic cash account.

- Activity is grouped by the recorded calendar date and sorted deterministically within a day.
- Incoming money keeps its title/note and links back to its plan page.
- Fund activity distinguishes deposit, withdrawal and opening rows and preserves the movement source: manual, opening/migration, plan execution, direct allocation, or income-deletion reversal.
- Investment activity distinguishes buy/sell, preserves optional notes, and labels rows linked to a plan or incoming-money record.
- Archived assets remain identifiable because historical activity resolves against `allAssets`; orphan references are shown explicitly rather than silently omitted.
- The page has its own date range, category chips, Persian-normalized search, and recorded-volume summary cards.
- Financial values use the existing privacy-sensitive rendering boundary.

## Deliberate limits

This timeline is a projection, not a new ledger. Poolamkoo does **not** infer expenses, wallet/bank balance, transfer causality, or an intraday execution timestamp that is not present in the source data. Same-day `createdAt` values are used only for stable display ordering.

## Data / deployment impact

- IndexedDB remains **schema 8**.
- No backup, Recovery Snapshot, or Device Transfer format change.
- No market-provider change.
- No new environment variable or Vercel setting.
- Background Push remains paused by default.
- Service Worker cache: `poolamkoo-v65`.
