# v1.0.1 — Public launch & quota hardening

`v1.0.1` یک Patch Release برای آماده‌سازی معرفی عمومی پولم‌کو است. این نسخه Feature مالی جدید، Provider جدید یا migration داده اضافه نمی‌کند؛ تمرکز آن فقط کم‌کردن مصرف Upstream/Hosting و جلوگیری از retryهای مخرب هنگام rate limit است.

## چرا این Patch لازم بود؟

در `v1.0.0` نرخ‌های پایه BrsApi با cache یک‌دقیقه‌ای دریافت می‌شدند. BrsApi در مستندات عمومی خود در تاریخ 2026-08-30 سقف رایگان **1500 request/day** را اعلام می‌کند. یک cache یک‌دقیقه‌ای در بدترین حالت نظری تا 1440 refresh روزانه برای همان endpoint ایجاد می‌کند و حاشیه امن کمی باقی می‌گذارد.

Tindex نیز برای پلن رایگان **1 request/minute** و **100 request/day** را مستند کرده و `Retry-After` را روی 429 ارائه می‌دهد. Tindex در پولم‌کو فقط fallback/legacy است، اما Patch باید همچنان جلوی retry burst را بگیرد.

منابع بررسی‌شده در زمان آماده‌سازی این Release:

- https://brsapi.ir/free-api-gold-currency-webservice/
- https://tindex.app/developers/
- https://vercel.com/academy/optimize-your-vercel-account/fluid-compute

## تغییرات Launch hardening

- cache نرخ‌های پایه BrsApi از **60 ثانیه به 180 ثانیه** افزایش یافت؛ سقف نظری refresh همان endpoint از 1440 به حدود **480 بار در روز** کاهش پیدا می‌کند، با این توضیح که رفتار واقعی به cache/runtime میزبان وابسته است.
- cache Quote مستقیم TSETMC از **45 ثانیه به 120 ثانیه** و Search از **300 ثانیه به 600 ثانیه** افزایش یافت؛ History همچنان یک ساعت cache می‌شود.
- Tindex fallback همچنان 30 دقیقه cache و Legacy Quote/History یک ساعت cache دارند؛ هر refresh فقط حداکثر یک Legacy Tindex ID را می‌گیرد.
- پاسخ `Retry-After` Providerها خوانده می‌شود. خطاهای 429/blocked/unauthorized یک **Cooldown محافظتی best-effort در runtime گرم** ایجاد می‌کنند تا کلیک‌های تکراری یا burst یک instance Provider را دوباره نکوبد.
- Browser client پاسخ همان مجموعه Target را تا **30 ثانیه** reuse می‌کند؛ refresh تکراری سریع یک Function invocation تازه نمی‌سازد.
- پاسخ عمومی `/api/market` وقتی هیچ شناسه بورسی/legacy کاربر در Query نیست، `s-maxage=60` دارد تا Landing/Workspaceهای بدون Target بورسی بتوانند از CDN پاسخ مشترک بگیرند؛ درخواست‌هایی که Target بورسی دارند عمداً `private, no-store` می‌مانند.
- Settings → وضعیت بازار اکنون Guardrailهای Launch، cooldown فعال و diagnostic امن را نشان می‌دهد. Diagnostic همچنان قیمت، نماد، نام دارایی، market id، مبلغ مالی و Secret را شامل نمی‌شود.
- Service Worker cache به `poolamkoo-v68` bump شد تا Patch واقعی PWA یک worker جدید و مسیر Update قابل مشاهده داشته باشد.

## محدودیت‌های عمدی

- Cooldown حافظه‌ای یک **global quota counter** نیست و بعد از cold start یا روی instance/region دیگر مشترک نیست. منبع اصلی حفاظت، cache طولانی‌تر و معماری بدون polling است.
- هیچ Redis، database مرکزی یا telemetry مالی برای quota tracking اضافه نشده است.
- TSETMC را نامحدود فرض نمی‌کنیم؛ blocked/429 همچنان به Snapshot واقعی یا قیمت دستی fallback می‌کند.
- Background Push همچنان default-off/backlog می‌ماند و با این Patch عمومی نمی‌شود.
- IndexedDB همچنان **schema 8** است و Backup/Recovery/Device Transfer contract تغییر نمی‌کند.

## Gate انتشار

قبل از Commit/Tag/Release باید `npm run check:stable` کاملاً سبز باشد. علاوه بر Gate خودکار، در Vercel باید **Fluid Compute = Enabled** روی deployment فعال تأیید شود و بعد از اولین معرفی عمومی، Function Invocations و Provider 429/blocked در Observability بررسی شوند.
