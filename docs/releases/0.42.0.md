# v0.42.0 — Reports & reconciliation upgrade

این نسخه گزارش‌ها را از یک مرور تصمیمی صرف به یک لایه تطبیق واقعی بین داده‌های ثبت‌شده ارتقا می‌دهد؛ بدون ساخت حساب نقدی، حدس‌زدن مسیر پول یا ارائه پیش‌بینی/توصیه خرید و فروش.

## تطبیق ورودی تا اجرا

- کارت جدید «تطبیق جریان مالی این بازه» برای هر پول ورودی چهار عدد واقعی را کنار هم می‌گذارد: مبلغ ورودی، تخصیص ثبت‌شده، برنامه ثبت‌شده و اجرای ثبت‌شده.
- فاصله ورودی تا تخصیص و فاصله تخصیص تا برنامه صریح باقی می‌مانند؛ پوشش ناقص یا ثبت بیش‌ازمبنا به‌عنوان «نیاز به بررسی» نمایش داده می‌شود.
- اجرای ناقص به‌تنهایی خطای داده نیست و با وضعیت «در حال اجرا» از ناسازگاری ساختاری جدا می‌شود.
- اجرای بیشتر از مبلغ برنامه پنهان یا فقط به ۱۰۰٪ clamp نمی‌شود؛ مقدار overrun جداگانه در مدل تطبیق حفظ می‌شود.

## گردش واقعی صندوق و سرمایه‌گذاری

- Fund Movementهای واقعی همان بازه به واریز، برداشت و موجودی آغازین تفکیک می‌شوند.
- موجودی آغازین در خالص گردش دوره حساب نمی‌شود تا migration/opening balance به‌اشتباه «پول تازه» تلقی نشود.
- تراکنش‌های سرمایه‌گذاری همان بازه به خرید و فروش تفکیک می‌شوند و فقط «خالص جریان خرید» گزارش می‌شود؛ این عدد سود/زیان یا بازده نام‌گذاری نمی‌شود.
- هیچ رابطه‌ای بین Fund Movement و Income/Plan که در Schema ذخیره نشده باشد از روی تاریخ/متن حدس زده نمی‌شود.

## مرز وضعیت فعلی و بازه گزارش

- فیلتر تاریخ روی Income/Allocation/Plan و گردش واقعی Fund/Investment اعمال می‌شود.
- جدول ارزش فعلی و وزن سبد از **کل Ledger سرمایه‌گذاری** ساخته می‌شود، نه فقط خریدهای داخل بازه؛ بنابراین انتخاب یک بازه کوتاه دیگر خرید قدیمی را از موجودی فعلی حذف نمی‌کند.
- پوشش فعلی صندوق‌ها نیز مثل قبل current-state است و در UI توضیح داده می‌شود که با جریان دوره فرق دارد.

## خروجی و Privacy

- CSV جزئی حالا خلاصه تطبیق ورودی/تخصیص/برنامه و مجموع گردش صندوق/سرمایه‌گذاری بازه را نیز دارد.
- CSV همچنان raw transaction table، Backup payload یا Recovery metadata صادر نمی‌کند.
- متن مناسب اشتراک همچنان فقط درصد/وضعیت دارد و مبلغ‌ها و نام دارایی‌ها را حذف می‌کند.

## Data safety / architecture

- IndexedDB همچنان **schema 8** است؛ Migration جدیدی وجود ندارد.
- Backup/Restore و Device Transfer format تغییر نکرده‌اند.
- هیچ داده مالی جدیدی به Server یا Analytics ارسال نمی‌شود.
- Provider priority، Snapshot decision-safety و Background Push backlog بدون تغییر باقی می‌مانند.
- Service Worker cache به `poolamkoo-v66` ارتقا یافته است.
