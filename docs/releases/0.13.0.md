# v0.13.0 — Background Web Push

این نسخه هشدارهای v0.12 را از حالت «فقط هنگام اجرای اپ» به Web Push اختیاری ارتقا می‌دهد تا شرط بازار در زمان بسته بودن کامل PWA هم بتواند Notification واقعی ایجاد کند.

## معماری Local-First حفظ شده

- Push به‌صورت opt-in است و بدون آن تمام رفتار محلی v0.12 باقی می‌ماند.
- اطلاعات مالی شخصی، موجودی صندوق‌ها، تراکنش‌ها، قیمت خرید و گزارش‌ها همچنان فقط در IndexedDB دستگاه هستند.
- Backend فقط Push Subscription و حداقل اطلاعات لازم برای هشدار را نگه می‌دارد: شناسه نماد، نوع شرط، آستانه و state اجرای هشدار.
- کلید ناشناس دستگاه در مرورگر ساخته می‌شود و کلید Redis از SHA-256 همان token مشتق می‌شود.

## Web Push

- کاربر از کارت «هشدارهای بازار» Push پس‌زمینه را صریحاً فعال می‌کند.
- Subscription از Service Worker و VAPID ساخته می‌شود؛ Permission خارج از gesture کاربر درخواست نمی‌شود.
- Alertهایی که گزینه «اعلان مرورگر» دارند با Backend همگام می‌شوند.
- حذف، Pause/Resume یا تغییر state هشدار روی mirror سرور هم اعمال می‌شود.
- Push دریافتی توسط Service Worker حتی در حالت بسته بودن صفحه نمایش داده می‌شود.
- Service Worker state محلی `armed` و `lastTriggeredAt` را هم به‌روزرسانی می‌کند تا بازکردن بعدی اپ Notification تکراری نسازد.

## Backend سبک

- `POST /api/push/subscription` برای sync امن Subscription و Alert mirror.
- `DELETE /api/push/subscription` برای حذف device و unsubscribe.
- `GET /api/push/config` فقط public VAPID key و وضعیت آماده‌بودن Backend را برمی‌گرداند.
- `GET /api/cron/market-alerts` با `CRON_SECRET` محافظت می‌شود و Alertها را با Quote واقعی Tindex بررسی می‌کند.
- Upstash Redis REST بدون SDK جداگانه برای persistence کم‌حجم استفاده می‌شود.
- Subscriptionهای منقضی‌شده با پاسخ 404/410 Push Service خودکار از Redis حذف می‌شوند.

## Cron و سهمیه بازار

`vercel.json` به‌صورت پیش‌فرض Cron را ساعتی اجرا می‌کند. این فاصله عمداً محافظه‌کارانه است؛ اگر سهمیه Tindex بالاتر داری می‌توانی schedule را کوتاه‌تر کنی. هر نماد بورسی یکتا برای ارزیابی نیاز به Quote واقعی دارد، بنابراین cadence باید با quota سرویس بازار هماهنگ باشد.

## متغیرهای محیطی

```text
WEB_PUSH_VAPID_PUBLIC_KEY
WEB_PUSH_VAPID_PRIVATE_KEY
WEB_PUSH_VAPID_SUBJECT
UPSTASH_REDIS_REST_URL
UPSTASH_REDIS_REST_TOKEN
CRON_SECRET
```

VAPID private key، Redis token و `CRON_SECRET` هرگز نباید `NEXT_PUBLIC_*` باشند.
