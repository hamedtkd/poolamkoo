# v1.0.0-rc.2 — Product tour release-blocker fix

این Candidate فقط یک blocker واقعی از Manual RC Acceptance را اصلاح می‌کند و **Feature freeze** همچنان برقرار است.

## blocker مشاهده‌شده در RC1

- Overlay راهنمای سریع روی خود کنترل هدف قرار می‌گرفت؛ در نتیجه کاربر می‌دید راهنما درباره یک بخش حرف می‌زند اما همان بخش زیر لایه تیره قرار داشت.
- جست‌وجوی Desktop `data-tour` نداشت و مرحله جست‌وجو می‌توانست بدون Highlight واقعی در مرکز صفحه نمایش داده شود.
- مرحله Reports در Mobile به آیتمی اشاره می‌کرد که فقط داخل More Drawer وجود داشت و هنگام اجرای Tour قابل‌دیدن نبود.

## اصلاح RC2

- Overlay تمام‌صفحه با چهار Shade مستقل جایگزین شد تا اطراف Target تیره بماند اما خود Target داخل یک **Spotlight شفاف واقعی** قرار بگیرد.
- کنار Highlight برچسب «این بخش» و داخل Card عبارت «در حال نمایش» اضافه شد تا دقیقاً مشخص باشد آموزش مربوط به کدام ناحیه صفحه است.
- Desktop Global Search یک Target واقعی گرفت و Mobile Tour فقط به کنترل‌هایی اشاره می‌کند که در همان لحظه روی صفحه قابل‌دیدن‌اند.
- هنگام تغییر مرحله Target به نزدیک‌ترین موقعیت قابل‌دیدن Scroll می‌شود و اندازه/Visibility واقعی DOM دوباره سنجیده می‌شود.
- Production Browser Smoke اکنون بازشدن Tour، عدم هم‌پوشانی Shade با Target و وجود Target واقعی برای مرحله Search را بررسی می‌کند.

## مرز Release

- IndexedDB همچنان **schema 8** است.
- Backup/Recovery/Device Transfer contract تغییر نکرده است.
- Provider، backend مالی، account system، cloud sync یا Feature Family جدیدی اضافه نشده است.
- `npm run check:rc` همچنان Gate کامل Production را قبل از metadata acceptance اجرا می‌کند.

## Manual acceptance قبل از v1.0.0 stable

علاوه بر Gateهای RC1، راهنمای سریع یک‌بار روی Desktop و Mobile واقعی مرور شود: Highlight باید واضح باشد، Target زیر Overlay نرود و هیچ مرحله‌ای بدون Target قابل‌دیدن نماند. بقیه سناریوهای نصب/Update PWA، Backup → Restore، old-tab upgrade و Responsive/Theme همچنان الزامی‌اند.
