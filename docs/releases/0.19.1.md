# v0.19.1 — Landing route and React effect fixes

This patch fixes the two release-blocking issues found while validating v0.19.0 on Windows/Next.js 16.

## Fixed

- The replacement-install cleanup now removes the obsolete `app/(app)/page.tsx` left by v0.18 and earlier copies. Keeping that file beside the new public `app/(public)/page.tsx` made Next.js report two pages resolving to `/`.
- App bootstrap no longer calls a state-resetting retry function synchronously from the mount effect. Initial bootstrap starts in `loading`, performs IndexedDB work asynchronously, and keeps the same explicit retry action for recovery UI.
- Network status now uses `useSyncExternalStore` plus the shared hydration snapshot instead of synchronous `setState` calls inside an effect.
- Service-worker cache version bumped to `poolamco-v34` so deployed clients pick up the corrected shell cleanly.

## Replacement-install note

Poolamco releases are commonly copied over an existing source tree. `npm run check`, `npm run dev`, and `npm run build` all run `clean:obsolete`, so old route files that cannot be deleted by an overwrite-only copy are removed before Next.js scans routes.


> Superseded in v0.19.2: the financial route group is renamed from `(app)` to `(workspace)`, and replacement cleanup removes the entire legacy `(app)` tree plus stale generated Next.js route validators.
