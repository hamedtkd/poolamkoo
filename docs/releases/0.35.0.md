# Poolamkoo 0.35.0 — Verified schema migration release gate

> Release-gate hotfix: the JavaScript schema-6 browser fixture now ships an adjacent TypeScript declaration (`schema6-idb.d.mts`), so strict `tsc --noEmit` can type-check the migration smoke test before the browser gate runs. Runtime fixture behavior is unchanged.

v0.34 introduced the first IndexedDB schema upgrade in several releases: schema 6 → 7 for provider-scoped market identity. v0.35 does not change the data model again. Instead it turns that migration into a real production-browser release contract.

## What changed

- `npm run check:release` now creates a raw legacy schema-6 `poolyar-local` database inside the isolated release-browser profile before opening the current workspace.
- The fixture mirrors the shipped schema-6 Dexie stores and uses native IndexedDB version 60, matching Dexie's `version(6)` mapping.
- Opening `/dashboard` must upgrade the same database in place to schema 7/native version 70.
- The browser gate verifies legacy linked assets, Watchlist rows and Alerts survive and normalize to Tindex, while explicit TSETMC identity remains unchanged.
- The gate inspects the actual upgraded IndexedDB indexes and requires `[source+marketId]` on Watchlist/Alerts plus a non-unique raw `marketId` Watchlist index.
- It then inserts TSETMC and Tindex Watchlist rows with the same raw market id and requires both to coexist.
- After the migration scenario, the fixture origin is fully cleared and the existing fresh-onboarding, dashboard, Reports, mobile Drawer and PWA checks run unchanged.

## Safety boundaries

- The migration fixture lives only in the temporary browser profile created by the release smoke; it never reads a real browser profile or user database.
- Market, Push and Cloudflare requests stay blocked during the browser gate, so migration QA cannot consume provider quota or send financial data.
- No new database migration is introduced in v0.35: IndexedDB remains schema 7.
- Backup envelopes, Recovery Snapshot format, Device Transfer protocol, database name and primary keys are unchanged.
- BrsApi remains core primary, direct TSETMC remains exchange primary, and Tindex remains legacy/emergency fallback.

## Release contract

A release is not considered green unless the normal unit/lint/type/build checks and the real production-browser schema 6 → 7 upgrade scenario all pass through `npm run check:release`.
