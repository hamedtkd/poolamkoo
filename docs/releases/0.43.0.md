# v0.43.0 — v1.0 readiness hardening

این نسخه به‌جای اضافه‌کردن Feature Family جدید، مرزهای Release-critical موجود را برای نزدیک‌شدن به v1.0 سخت‌سازی می‌کند. مدل Local-first، Backup/Restore، Device Transfer و IndexedDB schema 8 بدون تغییر باقی می‌مانند.

## مرز Public / PWA

- Service Worker همچنان فقط از Workspace رجیستر می‌شود و Manifest فقط در route group برنامه advertise می‌شود.
- به‌خاطر scope ریشه‌ای لازم برای routeهای sibling، صفحه عمومی همچنان می‌تواند تحت کنترل Worker موجود باشد؛ اما navigationهای خارج از Workspace حالا صریحاً network-only هستند و در Cache Storage برنامه نوشته نمی‌شوند.
- Cache runtime به `poolamkoo-v67` ارتقا یافته و Release Browser Smoke بعد از رجیسترشدن PWA به `/` برمی‌گردد و نبودن Landing در Cache Storage را بررسی می‌کند.

## رفتار «بعداً» برای Update

- Update آماده همچنان فقط با تأیید صریح کاربر `SKIP_WAITING` می‌گیرد.
- وقتی کاربر «بعداً» را می‌زند، همان waiting worker در Session جاری به‌عنوان dismiss‌شده نگه داشته می‌شود؛ focus/visibility update-check همان notice را دوباره باز نمی‌کند.
- اگر waiting worker واقعاً عوض شود، Update جدید دوباره قابل نمایش است.

## Error UX و Data Safety

- Workspace error boundary دیگر `repairLocalData()` را به‌صورت عمومی اجرا نمی‌کند؛ یک خطای render/runtime به‌خودی‌خود مدرک خرابی دیتابیس نیست.
- مسیر اول «تلاش دوباره» است. اگر مشکل ادامه داشت، CTA صریح کاربر را به `Settings → سلامت داده محلی` می‌برد و لینک Data Safety برای Backup/Recovery باقی می‌ماند.
- ترمیم deterministic همچنان فقط داخل Data Health انجام می‌شود و قبل از نوشتن Recovery Snapshot می‌سازد.

## Release gate و مستندات

- تست‌های PWA boundary/update برای network-only public navigation و dismiss همان waiting worker گسترش یافته‌اند.
- `tests/v1-readiness.test.ts` قرارداد نسخه، schema، error-boundary safety، Public/PWA boundary و مستندات audit را قفل می‌کند.
- `docs/audits/v1-readiness-v0.43.md` نتیجه Audit پیش از v1 را ثبت می‌کند.

IndexedDB در schema 8 باقی می‌ماند؛ Backup/Recovery/Device Transfer format، market provider priority، analytics boundary، zero-cost deployment و Background Push backlog تغییری ندارند.
