# Data safety model

پولم‌کو Local-First است؛ این یعنی داده مالی اصلی داخل IndexedDB همان Origin نگه داشته می‌شود، نه روی سرور مرکزی.

## سه لایه حفاظت

1. **IndexedDB اصلی** برای کار روزمره.
2. **Recovery Snapshot محلی** برای برگشت از حذف یا Restore اشتباه. این Snapshot در همان Browser Storage است و در برابر پاک‌شدن Site Data یا خرابی دستگاه محافظت نمی‌کند.
3. **Backup فایل** برای نسخه مستقل از مرورگر. برای استفاده جدی، نسخه رمزنگاری‌شده را در فضای دیگری مثل دیسک دوم یا فضای ابری شخصی نگه دارید.

## یادآوری Backup

بعد از حداقل ۲۴ ساعت استفاده معنادار، اگر بکاپی ثبت نشده باشد اپ پیشنهاد بکاپ می‌دهد. بعد از بکاپ، اگر ۷ روز بگذرد دوباره یادآوری فعال می‌شود. کاربر می‌تواند آن را ۳ روز Snooze کند.

## Recovery history

حداکثر ۵ Snapshot جدید نگه داشته می‌شود. Snapshot خودکار حداکثر روزی یک بار ساخته می‌شود و عملیات تخریبی مهم نیز قبل از اجرا Recovery Point می‌سازند.

## Restore

قبل از جایگزینی داده با Backup فایل یا Recovery Snapshot، وضعیت فعلی محلی ذخیره می‌شود. Import فقط جدول‌های داده اصلی را جایگزین می‌کند و متادیتای دستگاه و Recovery history را پاک نمی‌کند.

## محدودیت صادقانه

Browser Storage بکاپ دائمی نیست. حتی اگر مرورگر Persistent Storage را تأیید کند، کاربر یا سیستم همچنان می‌تواند Site Data را پاک کند. تنها Backup خارج از همان Browser Profile یک نسخه مستقل محسوب می‌شود.
