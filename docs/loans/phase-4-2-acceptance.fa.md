# پذیرش Phase 4.2: موتور ریسک و سلامت وام

## Scope بسته‌شده

این فاز موتور ریسک Local-First را روی داده‌های موجود وام فعال می‌کند. اتصال پیشرفته به تازگی Quote، هشدار `quote_stale`، فاصله بازده از هزینه وام و Background Push ریسک در Phase 4.3 باقی می‌ماند.

## سیاست ریسک

برای هر وام فعال دو نوع Policy مدیریت‌شده ساخته می‌شود:

- `reserve_runway_below`: کاهش پوشش ذخیره زیر مرز احتیاط
- `loss_budget_exceeded`: عبور زیان باز هر دارایی متصل از بودجه زیان وام

مرز پیش‌فرض ذخیره حداکثر ۳ قسط است. اگر هدف ذخیره کمتر از ۳ قسط باشد، همان هدف مرز هشدار می‌شود.

بودجه زیان از `riskBudgetInstallments` قرارداد می‌آید و به تومان ثابت تبدیل نمی‌شود. بنابراین اگر مبلغ قسط قرارداد تغییر کند، معنای اقتصادی Policy همچنان «چند قسط زیان» باقی می‌ماند.

## Hysteresis و Anti-spam

هشدارها از State پایدار `armed` استفاده می‌کنند.

- ذخیره زیر مرز، Alert را Trigger می‌کند.
- برای نمونه مرز ۳ قسط، Alert فقط بعد از برگشت به ۴ قسط دوباره Armed می‌شود.
- زیان باز بعد از عبور از بودجه Trigger می‌شود.
- Alert زیان فقط بعد از کاهش زیان به ۸۰٪ بودجه یا کمتر دوباره Armed می‌شود.

این فاصله Trigger و Rearm جلوی اعلان رفت‌وبرگشتی در نوسان‌های کوچک را می‌گیرد.

## محاسبه زیان

Risk Engine برای حد زیان از **زیان باز موقعیت** استفاده می‌کند، نه سود و زیان تحقق‌یافته تاریخی.

اگر یک دارایی کاملا فروخته شود، Alert فعال مربوط به موقعیت باز آن از Policy مدیریت‌شده حذف می‌شود.

## Guard داده بازار

در Phase 4.2، Alert خودکار زیان فقط وقتی قابل Trigger است که قیمت تصمیم‌پذیر باشد.

- Quote زنده قابل استفاده است.
- قیمت دستی معتبر قابل استفاده است.
- Snapshot محلی برای نمایش ارزش حفظ می‌شود، اما Alert خودکار زیان را Trigger نمی‌کند.
- نبود قیمت قابل اتکا وضعیت `unavailable` می‌سازد، نه سود/زیان ساختگی.

Freshness دقیق زمانی و هشدار Quote قدیمی در Phase 4.3 اضافه می‌شود.

## UX سلامت وام

صفحه هر وام Tab جدید «ریسک» دارد که نشان می‌دهد:

- وضعیت کلی: در محدوده برنامه، احتیاط، یا نیازمند اقدام
- تعداد مرزهای عبورکرده
- تعداد Policyهای نزدیک به مرز
- تعداد Policyهای نیازمند داده قابل اتکا
- وضعیت ذخیره
- وضعیت بودجه زیان هر دارایی
- Armed / Disarmed بودن هر Alert
- روشن یا خاموش بودن پایش
- روشن یا خاموش بودن Browser Notification برای هر Alert

Dashboard و لیست وام‌ها نیز از همین Health Summary استفاده می‌کنند و دیگر فقط به Rule ساده `reserve < 3` متکی نیستند.

## Local-First و حریم خصوصی

تمام ارزیابی Phase 4.2 روی دستگاه انجام می‌شود.

- Risk Engine درخواست شبکه مستقل ندارد.
- State Alert در `loanRiskAlerts` همان IndexedDB ذخیره می‌شود.
- Browser Notification فقط در صورت Permission قبلی کاربر نمایش داده می‌شود.
- Phase 4.2 هیچ Payload جدیدی برای Background Push تعریف نمی‌کند.

## تست‌های اضافه‌شده

- ساخت Policy ذخیره و موقعیت‌های باز
- حذف موقعیت کاملا فروخته‌شده از Policy زیان
- Trigger و Rearm ذخیره با Hysteresis
- اندازه‌گیری زیان در واحد قسط
- Trigger و Rearm بودجه زیان
- عدم Trigger از Snapshot
- Health Summary برای حالت سالم، احتیاط و بحرانی
- عدم ساخت Policy برای وام بسته
- Wiring موتور ریسک به Runtime و UI
- تایید Local-First بودن Hook ریسک
